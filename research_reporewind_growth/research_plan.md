# RepoRewind adoption research plan

## Main question

What is RepoRewind missing to become a compelling, trusted, easy-to-try GitHub project that earns sustained adoption, contributions, and stars without diluting its local-first cinematic Git-history product?

## Research tracks

### 1. Competitive landscape and product whitespace

Compare current Git-history visualization and repository-understanding tools using their official repositories and documentation. Record their positioning, adoption signals, strongest workflows, installation friction, sharing mechanics, and the underserved space RepoRewind can own.

### 2. GitHub discovery, activation, and contribution patterns

Study official GitHub guidance plus successful open-source developer tools to identify concrete practices that improve discovery, first-run activation, trust, contributor conversion, and release momentum. Separate durable product loops from superficial star-chasing tactics.

### 3. Distribution and share-loop feasibility

Research current official platform capabilities relevant to a one-command local experience, GitHub Actions-generated artifacts, embeddable/shareable history films, and privacy-safe repository analysis. Identify practical constraints so roadmap proposals remain technically credible.

## Synthesis method

Combine the external findings with a repository-grounded audit of RepoRewind. Prioritize recommendations using user impact, differentiation, effort, risk, and dependency order. The final `ROADMAP.md` will define measurable outcomes and acceptance criteria rather than promising virality or treating stars as the only success metric.
