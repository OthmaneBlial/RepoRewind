# RepoRewind 0.2.0 release candidate — publication pending

RepoRewind 0.2.0 is implemented on `main`, but it is not a published release yet. The public npm package, clean-install verification, provenance statement, `v0.2.0` tag, and matching GitHub Release remain one unfinished activation gate.

Use the current source build today:

```bash
git clone https://github.com/OthmaneBlial/RepoRewind.git
cd RepoRewind
npm ci
npm run reporewind -- /path/to/your/repository
```

The command analyzes the checked-out first-parent history, starts a read-only server on a random `127.0.0.1` port behind an unpredictable session path, opens the browser, and loads the validated history automatically. Press <kbd>Ctrl C</kbd> to stop the session. Use `--no-open` on a remote shell.

## Candidate changes

- The real application is available as a one-click [guided fictional case](https://othmaneblial.github.io/RepoRewind/play/?case=rebuild).
- `reporewind [repository]` is the primary local workflow; `reporewind analyze` remains the portable JSON workflow.
- The candidate npm tarball has no runtime dependencies, includes only reviewed distributable files, and passes exact-package smoke tests.
- The README now starts with real moving proof, a truthful source path, the expected result, and the local-first privacy contract.
- Film export starts with Share Safety and can produce a story pack containing four poster/still PNGs, the trailer, GitHub-ready Markdown, a privacy report, and a checksum manifest.
- Story Director proposes explainable Git-backed chapters that can be reordered, excluded, retitled, and rendered into the selected trailer/story pack.
- The Insights desk exposes eight bounded archaeology views with explicit limits and links to supporting evidence.
- A reproducible performance envelope covers 120, 1,000, and 5,000-commit histories through analyzer, browser, playback, and story-pack paths.
- If WebGL cannot start, the same archive opens as a text-first evidence workspace with search, Insights, comparison, Story Director navigation, and poster export.

## Migration

The archive schema remains at version 1. Source-checkout users can generate a portable archive with:

```bash
npm run reporewind -- analyze /path/to/repository \
  --output ./reporewind-history.json
```

After npm publication is independently verified, the equivalent public command will be:

```bash
npx reporewind analyze /path/to/repository \
  --output ./reporewind-history.json
```

No archive migration is required.

## Supported versions and limits

- Node.js 24 is recommended; Node.js 22.13 or newer is supported.
- The CLI is designed for current Git on Linux, macOS, and Windows; the exact public artifact still requires clean-install verification on all three.
- The one-command session binds only to IPv4 loopback and does not fetch refs, LFS objects, or submodules.
- Histories are limited to 256 MB, 250,000 commits, and 2,000,000 file-change entries. Use `--max-commits` earlier on ordinary laptops.

## Rollback

The public [`v0.1.0`](https://github.com/OthmaneBlial/RepoRewind/releases/tag/v0.1.0) source release remains the latest stable release. Do not create or move a `v0.2.0` tag until the registry artifact, provenance, live playground, README command, and displayed version agree.

Once an npm name/version is published it is immutable. If `0.2.0` must later be withdrawn, deprecate it with a specific recovery message, keep the GitHub release and checksums available for investigation, fix forward with `0.2.1`, and move the `latest` dist-tag only after the replacement passes the complete release gate.
