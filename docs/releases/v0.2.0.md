# RepoRewind 0.2.0 — Your repository, one command away

RepoRewind 0.2.0 turns the previous clone-and-import workflow into one supported command:

```bash
cd /path/to/your/repository
npx reporewind .
```

The command analyzes the checked-out first-parent history, starts a read-only server on a random `127.0.0.1` port behind an unpredictable session path, opens the browser, and loads the validated history automatically. Press <kbd>Ctrl C</kbd> to stop the session. Use `--no-open` on a remote shell.

## What changed

- The real application is now available as a one-click [interactive playground](https://othmaneblial.github.io/RepoRewind/play/).
- `reporewind [repository]` is the primary local workflow; `reporewind analyze` remains the portable JSON workflow.
- The npm tarball has no runtime dependencies, includes only reviewed distributable files, and is smoke-tested after clean installation on Linux, macOS, and Windows.
- The README now starts with a real 12-second replay, the canonical command, expected output, and the local-first privacy contract.
- Film export now starts with Share Safety and can produce a story pack containing four poster/still PNGs, the trailer, GitHub-ready Markdown, a privacy report, and an artifact checksum manifest.
- Story Director proposes explainable Git-backed chapters that can be reordered, excluded, retitled, and rendered into the selected trailer/story pack.
- The Insights desk turns existing Git metadata into eight bounded archaeology views, documents what each metric can and cannot prove, and links every ranked result to supporting evidence without depending on the 3D city.
- A reproducible performance envelope now measures 120, 1,000, and 5,000-commit histories through the real analyzer, browser, playback, and story-pack paths; deterministic renderer tiers bound interactive pixel and shadow cost for denser cities.
- If WebGL cannot start, the same archive now opens as an evidence workspace with search, Insights, timeline comparison, Story Director jumps, and a public-safe 1200×630 poster export instead of treating the repository as unsupported.

## Migration

The existing archive command remains compatible. Source-checkout users can continue to run:

```bash
npm run analyze -- /path/to/repository --output ./reporewind-history.json
```

Installed users should prefer:

```bash
npx reporewind analyze /path/to/repository --output ./reporewind-history.json
```

Archive schema version 1 is unchanged. No archive migration is required.

## Supported versions and limits

- Node.js 24 is recommended; Node.js 22.13 or newer is supported.
- Current Git on Linux, macOS, and Windows is exercised in CI.
- The one-command session binds only to IPv4 loopback and does not fetch refs, LFS objects, or submodules.
- Histories are limited to 256 MB, 250,000 commits, and 2,000,000 file-change entries. Use `--max-commits` earlier on ordinary laptops.

## Rollback

The public `0.1.0` source release remains available on GitHub. For scripted JSON generation, pin either CLI version explicitly:

```bash
npx reporewind@0.2.0 analyze . --output reporewind-history.json
```

Once an npm name/version is published it is immutable. If `0.2.0` must be withdrawn, deprecate it with a specific recovery message, keep the GitHub release and checksums available for investigation, fix forward with `0.2.1`, and move the `latest` dist-tag only after the replacement passes the complete release gate.

## Verification

The release is complete only when the Git tag, GitHub Release, npm registry version, provenance statement, README command, live playground, and locally installed `reporewind --version` all agree on `0.2.0`.
